# 영상 대본 작성 브리프 — Sinchon Guide 소개 영상

이 문서는 Gemini에게 그대로 전달할 자료입니다. 이 문서 하나만으로 대본을 쓸 수 있도록 필요한 정보를 전부 인라인으로 넣었습니다. 별도 자료 없이도 작업 가능하지만, 포스터 PDF와 앱 스크린샷을 함께 첨부하면 더 정확합니다.

---

## 0. 영상 개요

- **길이**: 5분 내외
- **형식**: 두 파트로 구성됩니다.
  1. **포스터 설명** — 화면에 포스터(A3, "Sinchon Guide" 소개 포스터)를 띄워 놓고 프로젝트를 설명
  2. **실기기 시연** — Android 에뮬레이터에서 앱을 직접 조작하며 보여줌
- **제작자**: 최윤섭 (개인 프로젝트, 대학 UX/앱 개발 과제)
- **목적**: 이 앱이 무엇을 하는지, 어떻게 동작하는지, 왜 이렇게 설계했는지를 짧은 시간 안에 전달

**요청하는 산출물**: 시간대별(타임스탬프) 구성의 한국어 대본. 각 구간마다 "화면에 무엇이 떠 있는지(포스터의 어느 섹션 / 앱의 어느 화면)"와 "그 순간 말할 대사"를 함께 적어 주십시오. 구성 예시는 §5를 참고하되, 더 나은 흐름이 있다면 자유롭게 재구성해도 됩니다.

## 1. 앱 소개

**이름**: Sinchon Guide (신촌 가이드)

**한 줄 요약**: 사용자가 자유 문장으로 원하는 장소를 말하면, 신촌 지역에서 지금 영업 중이면서 가장 가까운 실제 가게를 찾아 걸어가는 길까지 안내하는 앱입니다.

**서비스 설명 (내레이션에 그대로 녹여도 되는 문장)**:
> 신촌 가이드는 "어떤 곳을 찾으십니까?"라는 한 번의 질문에서 시작합니다. 사용자가 자유롭게 쓴 한 문장을 대규모 언어 모델이 장소 유형으로 해석하고, 실시간으로 주변의 실제 가게를 찾아, 지금 영업 중이면서 가장 가까운 곳을 골라, 도보 경로까지 지도에 그려 드립니다. 자체 장소 데이터베이스 없이 전 과정이 실시간 데이터로 동작합니다.

**핵심 기능 4가지**:
1. **문장으로 찾습니다** — 원하는 것을 그대로 적으면 됩니다. 카테고리 버튼이 없습니다.
2. **가까운 곳을 먼저 표시** — 반경 1.2km 안 도보 거리 순으로 한 곳을 먼저 제시합니다.
3. **지금 열려 있는지 확인** — 평점·영업 중 여부를 실시간 확인하며, 닫은 곳은 올리지 않습니다.
4. **걸어가는 길까지 안내** — 도보 경로를 지도에 그리고, 안내받은 장소를 기록으로 남깁니다.

## 2. 요청 처리 파이프라인 (6단계)

앱이 질문 하나를 처리하는 과정입니다. 포스터에도 이 순서대로 그려져 있으니, 포스터를 짚어가며 설명하는 구간에 그대로 쓸 수 있습니다.

| 단계 | 하는 일 | 담당 서비스 |
|---|---|---|
| ① 질문 | 사용자가 "조용한 카페"처럼 자유 문장을 입력 | 앱 화면 |
| ② 분류 | 문장에서 유형·키워드를 추출 (예: cafe, 또는 "당구장" 같은 임의 키워드) | Gemini Flash-Lite (대규모 언어 모델) |
| ③ 탐색 | 반경 1.2km 안의 실제 가게 후보를 찾음 | Kakao 지역 검색 |
| ④ 보강 | 가장 가까운 8곳에 한해 평점·영업 중 여부를 채움 | Google Places |
| ⑤ 랭킹 | 점수순으로 정렬 (§4의 알고리즘 참고) | 자체 스코어러 |
| ⑥ 안내 | 도보 경로를 계산해 지도에 그림 | TMAP · Naver Maps |

**말로 풀면**: "이 앱은 장소 데이터를 자체적으로 갖고 있지 않습니다. 질문이 들어올 때마다 이 6단계를 실시간으로 거쳐 결과를 만듭니다."

## 3. 기술적 특징 (왜 이렇게 만들었는가)

1. **도보 경로는 국내 서비스로 계산합니다.** 해외 지도 서비스의 경로 API는 국내 정밀 지도 데이터의 국외 반출 제한 때문에 신촌 구간의 경로를 반환하지 못합니다. 국내 사업자인 TMAP의 보행자 경로 API를 사용합니다.
2. **탐색과 정보 보강을 나눠 맡깁니다.** 장소를 찾는 일은 반경 검색이 가능한 Kakao 지역 검색이 맡고, Kakao가 제공하지 않는 평점·영업 중 여부만 Google Places로 가장 가까운 8곳에 한해 채웁니다.
3. **하나가 실패해도 화면은 뜹니다.** 평점 조회나 문장 분류가 실패해도 해당 값만 비운 채 나머지는 정상 동작합니다. 외부 서비스가 요청을 거절하면 그 사유를 화면에 그대로 남깁니다.

이 부분은 "왜 API를 4개나 나눠 썼는가"에 대한 답이므로, 기술적 깊이를 보여주고 싶은 구간에 배치하면 좋습니다.

## 4. 추천 알고리즘 — 어떻게 한 곳을 고르는가

이 앱의 핵심입니다. 영상에서 시연할 실제 검색 결과와 자연스럽게 연결할 수 있는 부분이므로, 포스터 설명과 시연 사이를 잇는 다리로 쓰는 것을 추천합니다.

**후보 하나에 매겨지는 4개 신호**:

| 신호 | 출처 | 정보가 없을 때 |
|---|---|---|
| 도보 거리 | 좌표로 직접 계산 | 항상 있음 |
| 평점 | Google Places | 3.5점으로 간주 (불이익 없음) |
| 영업 중 여부 | Google Places | 페널티 없음 (모름 ≠ 닫힘) |
| 방문 횟수 | 사용자 본인의 방문 기록 | 0 |

**점수 공식**:
```
점수 = −(도보분 × 10) + 평점 + 0.5 × min(방문횟수, 4) − 1000 × (영업 종료 여부)
```

**말로 풀면 (그대로 인용 가능)**:
- 1분 차이가 10점이라, 평점이나 방문 이력으로는 뒤집을 수 없습니다. **기본은 가까운 순**입니다.
- 영업이 끝난 곳은 1000점이 깎여, 아무리 가깝고 평점이 높아도 **항상 최하위**로 밀려납니다.
- 평점이 없는 곳은 3.5점으로 간주해 **정보가 없다고 불이익을 주지 않습니다.**

**계산 예시 (카페 검색, 후보 4곳)** — 실제 공식으로 계산된 값입니다:

| 후보 | 도보 | 평점 | 상태 | 방문 | 점수 | 순위 |
|---|---|---|---|---|---|---|
| A | 2분 | 4.1 | 영업 중 | 0회 | −15.9 | 1위 |
| D | 3분 | 4.3 | 영업 중 | 2회 | −24.7 | 2위 |
| C | 3분 | 없음 | 모름 | 0회 | −26.5 | 3위 |
| B | 1분 | 4.7 | 영업 종료 | 0회 | −1005.3 | 4위 |

가장 가깝고(1분) 평점도 가장 높은(4.7) B가 **영업 종료라는 이유만으로 꼴찌**로 밀리는 것이 이 알고리즘의 핵심을 가장 잘 보여주는 사례입니다. 대본에서 이 사례를 직접 언급하면 좋습니다.

산출된 점수 순서대로 화면에 후보들이 나열되고, 1위 후보가 대표 카드로 제시됩니다.

## 5. 에뮬레이터 시연 시나리오

Android 에뮬레이터에서 실제로 조작할 화면과 순서입니다. 대본에서 이 순서를 그대로 따르거나 재구성해 써 주십시오.

1. **질문 화면** — 앱을 켜면 카테고리 버튼 없이 입력창 하나만 있습니다. "조용한 카페"처럼 자유 문장을 입력하고 "찾기"를 누릅니다. → 이 순간이 §2의 ①②단계(질문→분류)가 실제로 일어나는 지점입니다.
2. **추천 결과 화면** — 상단에 대표 카드(별점·영업중 뱃지·도보 시간 표시), 그 아래 "다른 후보" 목록이 스크롤됩니다. 후보를 탭하면 그 후보가 대표 카드로 교체됩니다(화면 전환이 아닙니다). → §4의 점수 계산 결과가 눈으로 드러나는 지점입니다.
3. **"이 장소로 안내" 버튼** → 길안내 화면으로 이동합니다.
4. **길안내 화면** — 지도 위에 도보 경로선, 목적지 핀, 현재 위치 점이 표시됩니다. 하단 카드에 별점·영업 상태·주소가 있습니다. "네이버 지도로 안내" 버튼을 누르면 네이버 지도 앱의 길찾기로 넘어갑니다(시연에서는 누르지 않아도 됩니다). "다시 추천받기"·"홈" 버튼으로 돌아갈 수 있습니다.
5. **방문 기록 화면** — 질문 화면 상단 ☰ 버튼으로 진입. 지금까지 안내받은 장소 목록이 최신순으로 보입니다. "기록 지우기"를 누르면 확인 팝업이 뜨고, 지운 뒤에도 목록에서만 사라진다는 점을 안내합니다(추천에는 계속 반영됨).

**시연 중 언급하면 좋은 점**:
- 카테고리 버튼이 없다는 것 자체가 이 앱의 설계 포인트입니다(§1-1).
- 결과 화면의 별점·영업중 뱃지가 §4의 "정보 없을 때" 규칙과 연결됩니다 — 평점이 없는 후보는 "평점 없음"이라고 명시되지, 빈칸으로 사라지지 않습니다.
- 길안내 화면의 경로선은 §3-1에서 설명한 TMAP이 계산한 실제 경로입니다.

**촬영 시 주의할 점 (대본에는 필요 없지만 화면에 그대로 보이니 참고)**:
- 에뮬레이터의 "현재 위치"는 개발 편의를 위해 연세대학교 학생회관 좌표로 고정되어 있습니다. 실제 GPS가 아니라 고정값이므로, 지도에서 사용자 위치가 항상 같은 자리에 찍히는 것이 정상입니다.
- 길안내 화면에 경로선이, 추천 결과 화면에 별점이 정상적으로 표시되려면 백엔드가 외부 API 키(TMAP, Google, Kakao, Gemini)를 정상적으로 물고 있어야 합니다. 촬영 전 실제로 값이 채워지는지 확인이 필요합니다.

## 6. 기술 스택 (짧게 언급할 경우 참고)

- **Frontend**: React Native · TypeScript · Naver Maps SDK, Android 대상
- **Backend**: FastAPI · SQLite · JWT 인증
- **외부 API 4종**: Kakao 지역 검색(탐색) · Google Places(평점·영업중) · TMAP 보행자 경로 API(길찾기) · Gemini Flash-Lite(문장 분류)

영상에서는 이 목록을 전부 나열하기보다, "외부 서비스 4개를 조합해서 만들었다"는 사실 정도만 언급하고 §3(기술적 특징)에서 이유를 설명하는 것을 추천합니다.

## 7. 어투·표현 원칙

- **한국어 격식체(하십시오체)를 기본으로 합니다.** ("~합니다", "~됩니다") 발표 대본이므로 문장 끝을 완결된 형태로 씁니다.
- **과장되거나 유치한 표현을 쓰지 않습니다.** "완벽한", "최고의", "놀라운" 같은 수식어나 느낌표 남발을 피하고, 담백하고 사실 위주로 서술합니다.
- **"히어로"라는 단어를 쓰지 않습니다.** 가장 먼저 제시되는 추천 카드는 "대표 카드"라고 부릅니다.
- **없는 사실을 지어내지 않습니다.** 이 문서에 없는 통계·수치·사용자 후기를 만들어 넣지 마십시오.
- **"사용자"로 통일합니다.** "유저" 같은 캐주얼한 외래어 대신 "사용자"를 씁니다.

## 8. 대본 분량 가이드

한국어 발표 속도는 분당 약 300~350자입니다. 5분 영상이면 대본 전체가 **한국어 기준 약 1,500~1,750자** 분량이 되도록 조절해 주십시오(공백 포함, 화면 지시문 제외). 특정 구간(예: 시연)은 말이 없는 조작 시간이 섞이므로, 그 구간의 대사 분량은 더 적어도 됩니다.

**구성 예시 (참고용 — 그대로 따르지 않아도 됩니다)**:

| 시간 | 내용 | 화면 |
|---|---|---|
| 0:00–0:30 | 오프닝, 한 줄 소개 | 포스터 헤더 |
| 0:30–1:20 | 핵심 기능 4가지 + 6단계 파이프라인 | 포스터 |
| 1:20–1:50 | 기술적 특징 (왜 이렇게 만들었나) | 포스터 |
| 1:50–3:50 | 실기기 시연 (질문 → 결과 → 길안내 → 기록) | 에뮬레이터 |
| 3:50–4:30 | 추천 알고리즘 설명, 방금 본 결과와 연결 | 포스터 |
| 4:30–5:00 | 기술 스택 요약 + 마무리 | 포스터 |

## 9. 산출물 형식 요청

다음 형식으로 대본을 작성해 주십시오.

```
[0:00–0:XX] (포스터 / 에뮬레이터 — 어느 화면인지 명시)
대사: "..."

[0:XX–0:XX] (...)
대사: "..."
```

각 구간에 화면 지시문을 명확히 남겨 주십시오. 촬영자가 이 대본만 보고 "지금 포스터의 어느 부분을 가리켜야 하는지", "지금 앱에서 어떤 동작을 해야 하는지"를 알 수 있어야 합니다.
