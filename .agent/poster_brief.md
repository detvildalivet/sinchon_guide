# 포스터 디자인 브리프 — Sinchon Guide

이 문서 하나만 읽으면 포스터를 만들 수 있도록 필요한 모든 값을 아래에 인라인으로 넣었습니다. 별도로 코드 저장소를 열어볼 필요는 없습니다. 다만 첨부하는 이미지 파일들(포스터 예시 6장, 앱 스크린샷)은 실제로 봐 주십시오.

---

## 0. 과제 정의

- **결과물**: A3 세로(297×420mm) 포스터 1장, 인쇄용, 국문
- **주제**: "Sinchon Guide" — 신촌 지역 장소 추천 앱 소개
- **제작자**: 최윤섭 (2025143028) · 개인 프로젝트
- **제작 기간**: 2026.03 – 2026.07
- **레퍼런스 톤**: 대학 UX 수업(UXIM) 스타일의 서비스 소개 포스터. 별첨 이미지 6장(`poster_examples/` 폴더의 `KakaoTalk_20260728_112855319.jpg`, `..._01.jpg` ~ `..._05.jpg`)이 실제 참고 포스터입니다. 공통 골격은 다음과 같습니다:
  - 좌상단: 로고 + 서비스명 + 태그라인 한 줄 + 3~4줄 서비스 설명 + 해시태그 칩
  - 우상단: 폰 목업 2대를 사선으로 겹쳐 배치한 대표 이미지
  - RESEARCH → IDEATE → PROTOTYPE → DESIGN SYSTEM 순서의 섹션 밴드
  - 번호가 붙은 실제 앱 화면 스크린샷 + 한 줄 캡션
  - 컬러칩(HEX 표기) + 타이포 스케일 + 컴포넌트 목록으로 된 디자인 시스템 스트립
  - 하단에 QR 코드 + 제작자 정보

이 포스터는 위 골격에서 **RESEARCH·IDEATE를 쓰지 않습니다.** 설문·인터뷰 데이터가 없으므로 그 자리를 채우지 않고, 대신 헤더 바로 아래부터 **완성된 앱이 무엇을 하는지 · 어떻게 동작하는지 · 왜 그렇게 만들었는지**를 직접 보여주는 구성으로 시작합니다. PROTOTYPE(실제 화면) 다음에는 **"추천 알고리즘"** 전용 밴드를 추가합니다 — 참고 포스터 6장 어디에도 없는, 이 포스터만의 핵심 섹션입니다.

## 1. 표현 원칙 (전 구간 공통 — 반드시 지킬 것)

- 가장 먼저 제시되는 추천 카드는 **"대표 카드"**로 부릅니다.
- "승격되다" 대신 "교체되다"처럼 절제된 동사를 씁니다.
- **과장되거나 유치한 표현을 쓰지 않습니다.** 느낌표, "완벽한", "최고의", "놀라운" 같은 수식어, 감탄사 조의 카피를 금지합니다. 담백하고 사실 위주의 서술을 유지합니다.
- 전체 카피는 한국어 격식체(하십시오체)를 기본으로 합니다. 다이어그램·표 안의 짧은 라벨(예: "도보 거리", "영업 중")은 문장이 아니므로 격식체 어미를 억지로 붙이지 않습니다.

**앱 이름**: Sinchon Guide (한글 병기: 신촌 가이드)

**태그라인 (확정)**: `"어떤 곳을 찾으십니까?" — 한 문장이면 됩니다.`

**서비스 설명 (그대로 사용)**:

**해시태그 칩 (4개)**: `#자연어검색` `#가까운순` `#도보안내` `#신촌`

## 3. 레이아웃 — A3 세로 6밴드

A3는 참고 포스터들이 쓰는 A1보다 면적이 1/4입니다. 3단 좁은 컬럼 구성은 본문이 안 읽히는 크기까지 떨어지므로, **가로 전체폭 밴드를 위에서 아래로 쌓고, 꼭 필요한 두 곳만 좌우 2단**으로 나눕니다.

```
┌──────────────────────────────────────────┐
│ A. 헤더 + 대표 이미지          (~23%)    │  풀블리드 컬러 배경
├────────────────────┬─────────────────────┤
│                    │ C2a. 핵심 기능 4가지 │
│ C1. 요청 처리       ├─────────────────────┤  2단 (~25%)
│     파이프라인       │ C2b. 기술적 특징 3  │
│    (3단계 × 2줄)     │                     │
├────────────────────┴─────────────────────┤
│ D. 실제 화면 4컷              (~20%)     │  전체폭
├──────────────────────────────────────────┤
│ E. 추천 알고리즘              (~19%)     │  전체폭 — 포스터의 중심 섹션
├────────────────────┬─────────────────────┤
│ F1. 기술 스택      │ F2. 디자인 시스템   │  2단 (~9%)
├────────────────────┴─────────────────────┤
│ G. 푸터 (QR·크레딧)           (~4%)      │  하단까지 완전히 채움
└──────────────────────────────────────────┘
```

섹션 헤더에는 01/02/03 번호를 붙입니다. 예: "핵심 기능" · "기술적 특징" 블록은 번호 없이 소제목만, 그다음 D밴드는 **"02 실제 화면"**, E밴드는 **"03 추천 알고리즘 — 어떻게 한 곳을 고르는가"**처럼 이어집니다.

**여백 (A3 인쇄 기준)**

| 위치 | 값 |
|---|---|
| 상단·좌·우 | 12mm |
| **하단** | **여백 없음 — 포스터 맨 아래까지 내용을 채웁니다.** 재단선만 3mm 확보하고, 푸터(G)가 페이지 하단 끝까지 닿도록 배치합니다. |

**타이포 하한 (A3, 시야거리 약 50cm 기준 — 이 아래로 절대 내려가지 마십시오)**

| 요소 | 크기 |
|---|---|
| 앱명 | 54–64pt |
| 태그라인 | 16–18pt |
| 섹션 헤딩 | 13–15pt |
| 소제목 | 10–11pt |
| 본문 | **8.5–9pt (하한)** |
| 캡션 / HEX 코드 / 표 안 숫자 | 7–7.5pt |

**서체**: Pretendard 하나만 사용 (Bold / SemiBold / Regular 3웨이트).

## 4. 밴드별 상세 내용

### A. 헤더 + 대표 이미지

- 로고 마크: 완성됨(단순한 마크, 우상단 폰 목업 옆이 아니라 앱명 좌측에 배치)
- 앱명 + 한글 병기, §2의 태그라인, §2의 서비스 설명, §2의 해시태그 칩
- 대표 이미지: 폰 목업 2대를 사선으로 겹쳐 배치. 앞쪽 폰 = 추천 결과 화면, 뒤쪽 폰 = 길안내 화면.
- 하단(또는 별도 크레딧 위치)에 제작자 정보를 배치할 필요는 없습니다 — 크레딧은 G(푸터)에서 한 번만 표기합니다.

### C1. 요청 처리 파이프라인 (좌측 컬럼)

앱이 요청 하나를 처리하는 6단계를 보여줍니다. 좁은 컬럼에 맞게 **3단계씩 2줄**로 배치하고, 흐름이 끊기지 않도록 뱀 모양(오른쪽으로 → →, 아래로 꺾은 뒤 왼쪽으로 ← ←)으로 잇습니다. 각 단계 아래에는 그 단계를 실제로 처리하는 서비스 이름을 작게 붙입니다.

```
 ①  질문             →   ②  분류                →   ③  탐색
 "조용한 카페"            유형·키워드 추출              반경 1.2km
 자유 문장 입력           (cafe · "당구장")             실제 가게 후보
 ─────────                ─────────                     ─────────
 앱 화면                  Gemini Flash-Lite             Kakao 지역 검색
                                                              │
 ┌────────────────────────────────────────────────────────────┘
 │
 ⑥  안내             ←   ⑤  랭킹                ←   ④  보강
 도보 경로 · 지도 렌더    점수순 정렬                    평점·영업중,
 ─────────                (↓ 03. 추천 알고리즘)          가까운 8곳만
 TMAP · Naver Maps        ─────────                     ─────────
                          자체 스코어러                  Google Places
```

- 각 카드 구성: 번호(원문자) + 소제목(굵게) + 한 줄 설명 + 구분선 + 담당 서비스 이름.
- 캡션 문장은 넣지 않습니다. 다이어그램 자체로 블록을 마무리합니다.
- ⑤ 랭킹 카드에서 아래쪽 E밴드(03. 추천 알고리즘)로 짧은 지시선을 뺍니다.

### C2a. 핵심 기능 (우측 상단, 2×2 카드)

아이콘 + 제목 + 한 줄 설명. 아래 문구를 그대로 사용하십시오.

1. **문장으로 찾습니다**
   원하는 것을 그대로 적으면 됩니다. 카테고리 버튼이 없습니다.
2. **가까운 곳을 먼저 표시**
   반경 1.2km 안 도보 거리 순으로 한 곳을 먼저 제시합니다.
3. **지금 열려 있는지 확인**
   평점·영업 중 여부를 실시간 확인, 닫은 곳은 올리지 않습니다.
4. **걸어가는 길까지 안내**
   도보 경로를 지도에 그리고, 안내받은 장소를 기록으로 남깁니다.

**아이콘 방향**: 1=입력창/말풍선, 2=위치 핀, 3=시계 또는 영업중 표시, 4=발자국 또는 경로선. 네 아이콘의 선 굵기·스타일을 통일합니다. 각 카드 오른쪽 위에 작은 숫자(01~04)를 달아 D밴드의 화면 컷 번호와 매칭합니다.

### C2b. 기술적 특징 (우측 하단)

각 항목 = 제목 한 줄(굵게) + 설명. 아래 문구를 그대로 사용하십시오.

1. **도보 경로는 국내 서비스로 계산합니다**
   해외 지도 서비스의 경로 API는 국내 정밀 지도 데이터의 국외 반출 제한 때문에 신촌 구간의 경로를 반환하지 못합니다. 국내 사업자인 TMAP의 보행자 경로 API를 사용합니다.
2. **탐색과 정보 보강을 나눠 맡깁니다**
   장소를 찾는 일은 반경 검색이 가능한 Kakao 지역 검색이 맡고, Kakao가 제공하지 않는 평점·영업 중 여부만 Google Places로 가장 가까운 8곳에 한해 채웁니다.
3. **하나가 실패해도 화면은 뜹니다**
   평점 조회나 문장 분류가 실패해도 해당 값만 비운 채 나머지는 정상 동작합니다. 외부 서비스가 요청을 거절하면 그 사유를 화면에 그대로 남깁니다.

### D. 02 실제 화면 (전체폭)

폰 프레임 4개를 가로로 나열. 각 프레임 아래에 번호, 화면명, 한 줄 설명, 기술 포인트 한 줄을 붙입니다.

| # | 화면명 | 보여줄 상태 | 캡션 |
|---|---|---|---|
| 01 | 질문 | "조용한 카페" 입력된 상태, 버튼 없이 입력창 하나 | 카테고리 버튼 없이 문장 한 줄 · LLM이 유형/키워드로 해석 |
| 02 | 추천 결과 | 상단 대표 카드(별점·영업중 뱃지·도보 시간) + 아래 "다른 후보" 목록 | 한 곳을 먼저 제시하고 나머지는 아래에 · 탭하면 이동이 아니라 대표 카드로 교체 |
| 03 | 길안내 | 지도 위 경로선 + 목적지 핀 + 현재 위치 점 + 하단 정보 카드 | 선택한 한 곳만 실제 도보 경로 계산 · 경로를 지도 위에 직접 렌더 |
| 04 | 방문 기록 | 방문 기록 목록 + "기록 지우기" 확인 팝업 | 안내를 시작한 시점에 기록 · 지워도 추천에는 계속 반영 |

02번 컷 아래에 얇은 화살표/지시선으로 *"이 순서는 어떻게 정해지는가 ↓"*라고 적어 바로 아래 E밴드로 시선을 유도합니다.

### E. 03 추천 알고리즘 — 어떻게 한 곳을 고르는가 (전체폭)

이 앱이 한 곳을 고르는 방식을 보여주는, 이 포스터만의 핵심 섹션입니다. 좌→우 3블록으로 구성합니다.

**블록 1 — 후보 하나에 매겨지는 4개 신호**

| 신호 | 출처 | 정보 없을 때 |
|---|---|---|
| 도보 거리 | 좌표로 직접 계산 | 항상 있음 |
| 평점 | Google Places | 3.5점으로 간주 |
| 영업 중 여부 | Google Places | 페널티 없음 |
| 방문 횟수 | 사용자 본인 방문 기록 | 0 |

**블록 2 — 점수 공식** (숫자를 임의로 바꾸지 말고 그대로 표기):

```
점수 = −(도보분 × 10) + 평점 + 0.5 × min(방문횟수, 4) − 1000 × (영업 종료 여부)
```

계수 설명:
- **거리 계수 ×10** — 1분 차이가 10점입니다. 평점·방문 이력으로는 뒤집을 수 없는 크기이므로 기본 정렬은 가까운 순입니다.
- **−1000** — 어떤 조합으로도 복구되지 않습니다. 영업 종료는 항상 최하위로 밀려납니다.
- **평점 없으면 3.5점 / 방문 상한 4회** — 정보가 주어지지 않은 장소를 배제하지 않고, 다양한 선택지를 보장합니다.

**블록 3 — 계산 예시 (카페 검색, 후보 4곳)** — 실제 공식으로 계산된 값입니다. 숫자를 임의로 바꾸지 마십시오:

| 후보 | 도보 | 평점 | 상태 | 방문 | 점수 | 순위 |
|---|---|---|---|---|---|---|
| A | 2분 | 4.1 | 영업 중 | 0회 | −15.9 | 1위 |
| D | 3분 | 4.3 | 영업 중 | 2회 | −24.7 | 2위 |
| C | 3분 | 없음 | 모름 | 0회 | −26.5 | 3위 |
| B | 1분 | 4.7 | 영업 종료 | 0회 | −1005.3 | 4위 |

콜아웃 4개:
- **B**: 가장 가깝고 평점도 가장 높지만 닫혀 있어 최하위 → 영업 여부가 모든 것에 우선합니다.
- **A**: 평점이 D보다 낮아도 1분 더 가까워 1위 → 거리가 우선합니다.
- **D vs C**: 같은 3분 거리. 평점과 방문 이력이 순서를 갈랐습니다 → 동점일 때만 작동하는 결정자입니다.
- **C**: 평점이 없어도 3.5점으로 처리되어 D 바로 다음 → 모르는 정보에 벌점이 없습니다.

밴드 하단 마무리 문장(그대로 사용): **"산출된 점수 순서대로 화면에 후보들이 나열되고, 1위 후보가 대표 카드로 제시됩니다."**

## 6. 반드시 지킬 것 / 하지 말 것

- **"히어로"라는 단어를 쓰지 않습니다.** 대신 "대표 카드"를 씁니다. 과장되거나 유치한 수식어·감탄사도 쓰지 않습니다 (§1 참고).
- **포스터 하단에 여백을 남기지 않습니다.** 상·좌·우 12mm는 유지하되, 푸터(G)는 페이지 맨 아래까지 채웁니다.
- 본문 글자 크기 8.5pt 미만으로 내려가지 마십시오. 안 읽히면 섹션을 줄이십시오(예: E밴드 표를 4행 → 3행으로).
- 없는 설문·통계 수치를 새로 만들어 넣지 마십시오. 이 포스터에는 RESEARCH 섹션이 없습니다.
- 가상의 사용자 페르소나(이름·나이·인터뷰 인용 등)를 만들어 넣지 마십시오.
- "지도 앱 일반", "타 서비스" 등으로 일반화해서 언급하는 것은 괜찮지만, 특정 경쟁 서비스명을 단정적으로 거론하지 마십시오.
- E밴드의 점수 공식과 예시 표 숫자는 실제 코드 계산값입니다. 임의로 반올림하거나 바꾸지 마십시오.
- 전체 카피는 한국어 격식체(하십시오체)로 통일하십시오(§1의 예외 참고).
- **개발 과정·개인적 선택을 서술하지 않습니다.** "~로 정했습니다", "~를 고민했습니다" 같은 문장 대신, 완성된 앱이 지금 무엇을 하는지 서술합니다.
